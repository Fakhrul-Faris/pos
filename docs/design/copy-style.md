# Miki Copy Style — Replication Guide

**Status:** Active — v1.0  
**Also called:** Operational Empathy · Plain Relief  
**Use for:** Hub and vertical marketing, ads, emails, in-app micro-copy, Penpot wireframes  
**Draft copy by vertical:** [`marketing-copy.md`](marketing-copy.md) · Barbershop page: [`../modules/barbershop/marketing.md`](../modules/barbershop/marketing.md)

## What it is

Short, plain copy that names real operational pain, promises human relief (not growth hype), and kills the biggest objection in the same breath.

Platform-first on the hub (`/`). Vertical-specific language only on vertical pages (`/barbershop`, etc.). One idea per block. Headlines do the work; body is optional and never a feature list.

**One-line spec (for briefs):**

> Miki copy = short operational empathy. Name the shop's daily mess in plain words, promise relief in one line, kill the main objection beside it. Platform voice on the hub; vertical voice only on vertical pages. No feature paragraphs — headlines, tables, and fragments only. Calm, specific, Malaysian-practical. Never hype.

## Core principles

### 1. Pain before product

Open with the shop reality, not Miki's features.

- ✅ *Running a service shop is hard enough.*
- ❌ *Miki is an all-in-one queue and POS solution.*

### 2. One beat per block

Each section = **headline** (+ optional **one subhead** or **one table**). No paragraph stacks.

- ✅ Headline + 3 bullet fragments
- ❌ Five sentences explaining walk-ins, bookings, payments, reports, and offline

### 3. Platform on `/`, vertical on `/barbershop`

If it mentions chairs, barbers, haircuts, or per-barber — it's vertical copy, not hub copy.

| Page | Speaks about |
| :--- | :--- |
| Hub | Service shops, counter, queue, any business type |
| Vertical | That business's specific workflow |

### 4. Objection in the same breath

Every major claim pairs with the fear it removes.

- *14 days free · No card · No hardware bundle*
- *We never block checkout on cash or your own QR.*

### 5. Specificity, not hype

Use real objects: QR, tablet, DuitNow, closing, WhatsApp. Avoid abstract superlatives.

- ✅ *Close without the detective work*
- ❌ *Revolutionize your business* / *10x your revenue*

### 6. Italic = one emotional hinge

One italicized word or phrase per headline max. It marks the feeling, not decoration.

- *Running a service shop is hard enough.*
- *One platform. Pick your shop.*

## Structural templates

### Hero (hub or vertical)

```
[Headline — pain or outcome, 3–8 words + optional italic hinge]
[Subhead — one line, max ~12 words, names the system not features]
[CTA] · [Secondary CTA optional]
[Trust line — 3 fragments separated by ·]
```

### Section

```
[Headline — 3–7 words]
[Subhead — one line OR table OR 3 short bullets — never both long subhead and long bullets]
```

### Vertical picker card

```
[Shop type]
[Badge: Live / Soon]
[One line — workflow, not feature list]
```

### FAQ

```
[Question — plain language]
[Answer — 1–2 short sentences max]
```

## Voice attributes

| Attribute | Setting |
| :--- | :--- |
| **Register** | Conversational B2B — shop owner, not enterprise procurement |
| **Confidence** | Calm, assured — not loud or bro-marketing |
| **Warmth** | Empathetic — you've seen their day |
| **Humor** | Light touch only; never edgy or absurdist |
| **Jargon** | Avoid: solution, leverage, synergy, ecosystem, revolutionary |
| **Local** | Malaysian context when relevant: DuitNow, RM, no sales call |
| **Payments** | Never name partners on marketing; say "integrated QR & card" |

---

## Formatting rules

| Element | Rule |
| :--- | :--- |
| Headline length | ≤ 10 words ideal |
| Subhead | 1 line, ≤ 15 words |
| Body paragraph | Avoid on marketing pages; use tables/cards instead |
| Bullets | Fragments, not sentences; max 3 per section |
| CTAs | Verb-first, low friction: *Start free*, *See pricing*, *Join waitlist* |
| Trust lines | 3 items, middot-separated |
| Stats | Only if true and specific; no vanity stacking |

## Do / Don't

**Do**

- Name the mess (three apps, two phones, one tired owner)
- Promise relief (less chaos, close without detective work)
- Separate hub vs vertical copy strictly
- Use tables for payments, steps, verticals
- Lead with BYOD, no card, own DuitNow as trust

**Don't**

- List features in prose
- Open the hub with one vertical's pain
- Write compare sections as essays
- Promise revenue multiples
- Sound like a retail POS or crypto wallet

---

## Replication checklist

Before shipping copy, ask:

1. **Is this hub or vertical?** — Strip vertical language from hub.
2. **Can I cut the body?** — If yes, cut it.
3. **What's the one fear?** — Put the answer next to the claim.
4. **Is there one italic hinge?** — Not zero, not three.
5. **Would Baba / Basecamp / WGAC write a 5-line paragraph here?** — No → rewrite as headline + one line.

## Extending beyond the landing page

| Surface | Adjustment |
| :--- | :--- |
| **Emails** | Subject = headline. Body = 2–3 short blocks. One CTA. |
| **In-app empty states** | One line, operational: *No one waiting. Next walk-in shows up here.* |
| **Pricing page** | Principles in fragments; RM tables OK; no prose tiers |
| **Ads** | One pain + one relief + trust fragment |
| **Vertical launch** | Clone hub structure; swap hero + picker card + 1 problem line |
